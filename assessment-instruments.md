# DSPH AI Workshops — Baseline & Endpoint Assessment

Build both as Microsoft Forms (forms.office.com, Drexel login). The **endpoint form is the
baseline form plus Section E** — build the baseline, use Copy, rename, add Section E.
Settings: anyone in Drexel can respond, do NOT record names (One response per person OFF —
recording names would defeat the anonymous design), responses to Excel.

**Timing.** Baseline: link goes out with the Core 1 Outlook invitation and sits on the site's
home page ("before your first session"). Endpoint: administered in the last 5 minutes of
Core 4 (or by email right after), each term. People who join mid-series: have them take the
baseline before whichever session is their first — the pairing code handles the rest.

**Why this design.** Identical items at baseline and endpoint give a true pre/post on
knowledge and self-efficacy across the whole core series; the per-session feedback forms
(retrospective pre/post pair) cover session-level change. Together: series-level change,
session-level change, and page-level signal (quiz telemetry), with no identifiable data
anywhere.

## Section C — Confidence (self-efficacy)

"How confident are you that you could do each of the following **on your own, today**?"
(Likert 1–5: Not at all confident → Completely confident. Use one Likert grid question.)

1. Write a prompt with enough context, role, and format that the first response is usable
2. Use AI to summarize a long document or email thread, and check the summary against the
   original before relying on it
3. Decide which AI tool is permitted for a given kind of Drexel data
4. Build a reusable assistant (a custom GPT or Project) with its own instructions and a
   knowledge file, and test that its guardrails hold
5. Verify whether a citation or statistic an AI gives you is real before using it
6. Write a disclosure statement for AI-assisted work that is specific enough to be useful

(Items 1–6 map to Core 1, Core 2, Core 1/data rules, Core 3, Core 4, Core 4. Keep wording
IDENTICAL at baseline and endpoint, and stable across years.)

## Section D — Knowledge check (10 items)

One point each; correct answers marked ✔ (do not mark them in the form). Randomize option
order in Forms if you like, but keep item wording fixed. Items are written fresh (not
copied from the site's readiness quizzes) so the public quizzes don't contaminate the
measure.

1. Fundamentally, what does a large language model do to produce its answer?
   - Looks the answer up in a database of verified facts
   - ✔ Predicts likely next words based on patterns in its training data
   - Runs a live web search and summarizes the results
   - Applies a fixed set of rules written by its developers

2. An AI tool gives you a confident, detailed answer that turns out to be wrong. This is
   best described as:
   - A rare malfunction that indicates the tool is broken
   - ✔ A hallucination — fluent, plausible output not grounded in fact, which is a normal
     failure mode
   - Proof the tool was trained on bad data
   - Something that only happens with free-tier tools

3. Which of these may go into a **personal** (non-Drexel) ChatGPT or Claude account?
   - Anything, as long as you delete the chat afterward
   - De-identified patient records
   - Student grades without names attached
   - ✔ Public or otherwise Low Risk information only

4. You're signed in to Microsoft Copilot Chat with your Drexel account and Enterprise Data
   Protection is active. Per Drexel's AI Tools page, it is listed as usable with:
   - Low Risk data only
   - Moderate Risk data
   - ✔ High Risk data
   - Any data including PHI, without restriction

5. The most reliable way to check a citation an AI produced is to:
   - Ask the AI whether the citation is real
   - Check whether the journal name exists
   - ✔ Look the article up yourself in PubMed or the journal's site
   - Trust it if the authors' names look familiar

6. A colleague's prompt — "summarize this report" — gets a mediocre result. Which single
   change most improves it?
   - Adding "please" and asking again
   - Running it twice and comparing
   - ✔ Adding who the summary is for, what it will be used for, and the length and format
     needed
   - Switching to a larger model

7. You build a custom GPT and upload your grants calendar as a knowledge file. Asked about
   a deadline that is NOT in the file, the assistant will most likely:
   - Say nothing — it can only discuss the uploaded file
   - Always answer "I don't know"
   - ✔ Possibly produce a plausible-sounding answer anyway, unless its instructions tell it
     to refuse
   - Email the grants office for the answer

8. Under NIH policy (NOT-OD-25-132), a grant application substantially developed by AI:
   - Must include an AI-disclosure form
   - Is allowed if the PI edits the text carefully
   - ✔ Will not be reviewed, and post-award discovery can be treated as a misconduct matter
   - Is allowed for resubmissions only

9. For scientific writing (grants, manuscripts), the appropriate use of AI is:
   - Drafting the methods so the language is standardized
   - ✔ Brainstorming framings and critiquing a draft you wrote yourself
   - Writing the first draft, which you then reword
   - None — journals prohibit any AI involvement, including editing

10. Which task is the best candidate for an AI agent to run with minimal supervision?
    - Sending decisions to a funder based on its own analysis
    - Deleting duplicate files across a shared drive
    - ✔ Producing a weekly summary of public health news that you read before using
    - Answering student emails automatically

## Analysis notes

- **Primary:** paired change in Section C mean (and per item) and Section D total among
  matched codes; report unmatched cross-sections as a sensitivity analysis. McNemar or
  paired t/Wilcoxon as appropriate; n will be small — report effect sizes with CIs, not
  just p-values.
- **Interpretation guard:** endpoint responders are self-selected completers; say so
  whenever reporting.
- **Session-level change** comes from the feedback forms' retrospective pre/post pair;
  **page-level signal** from the quiz telemetry in GoatCounter (event paths like
  `quiz/data-cleaning/2of3` — attempts and score distributions per page, aggregate only).
- **IRB:** for internal program improvement, no IRB needed. If results may be presented or
  published (e.g., ASPPH), request an exempt determination BEFORE the baseline goes out —
  retroactive determinations are painful. The anonymous-code design with no identifiers
  makes exemption straightforward.
